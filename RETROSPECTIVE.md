# Project Retrospective

## 1. What Went Well?
- The project was developed with a clear and organized folder structure.
- User authentication and role-based access control were implemented.
- Students can browse laboratory equipment and submit booking requests.
- Staff can review booking requests and approve or reject them.
- Automated tests were added to verify important application functionality.
- Code quality was checked using Ruff, and a code review checklist was prepared.

## 2. What Could Be Improved?
- Staff equipment management could be expanded to allow staff to add new equipment and update existing equipment details.
- The equipment catalogue could include relevant images for each item to help students identify equipment easily.
- Improve maintainability by separating each class and its responsibilities clearly.

## 3. What Did We Learn?
- Organizing code into separate modules improves maintainability.
- Automated testing helps verify that application features work as expected.
- Code quality tools and review checklists support consistent development practices.
- Clear equipment information can improve the user experience.

## 4. Action Items
- Consider implementing staff functionality for adding and updating equipment.
- Add suitable images to the equipment catalogue.
- Continue running Ruff and automated tests when making future changes.
- Maintain the code review checklist for future development.

## 5. Conclusion
The project achieved its main objectives of providing equipment browsing, student booking requests, and staff booking approval functionality. Future improvements could focus on equipment management and a more informative catalogue with images.
